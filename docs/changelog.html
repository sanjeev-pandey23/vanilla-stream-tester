Stream Tester — Changelog

Developer-focused player · Sanjeev Pandey's Lab

v0.0.8 7 Aug 2026
Themes
  • New New clean theme — a new stylesheet (style-new.css) built from scratch alongside the existing brutalist theme. Design language: flat-2D surfaces, Inter / system-UI typeface, tight gray ramp (#f5f5f7 → #1d1d1f), and only three semantic accent colors — Blue (#007aff) for interactive elements, red for errors, green for the LIVE badge. No textures, no heavy drop shadows, no uppercase everywhere.
  • New Dark mode for Apple theme — full prefers-color-scheme: dark support via a single CSS variable-override block. All tokens shift to Apple's dark system palette (#000 page background, #1c1c1e / #2c2c2e surfaces, #0a84ff accent blue). Shadows gain opacity, interactive inputs get a surface-2 background lift so they read as elevated against the dark panel. No rules are duplicated — only the tokens change.
Bug Fixes
  • Fix Config panel layout shift on player load — when the left player panel grew taller as stats and logs populated, the CSS Grid row stretched the config panel to match. With align-content unset (defaulting to stretch), the inner grid redistributed the extra height between rows, visually shifting all controls. Fixed by setting align-content: start on .config-panel in both stylesheets so items always pack from the top.
  • Fix Share button height inconsistency — the inline Share button in the config panel (.btn-share-inline) had no explicit height, so font-metric differences between themes caused it to render at slightly different sizes. Fixed with a hard height: 28px and padding: 0 12px so vertical size is always controlled.
v0.0.7 7 Aug 2026
FairPlay DRM
  • New FairPlay DRM support — full EME implementation for Safari on macOS and iOS. MediaKeys and the server certificate are pre-created before src is assigned, keeping the encrypted-event handler on the fast path. Video and audio encrypted events are handled concurrently via a shared ensureAttached() promise so setMediaKeys is called exactly once regardless of how many sessions arrive.
  • New Certificate URL field — a Certificate URL input (shown automatically when FairPlay is selected as the key system) lets you supply the .cer endpoint. The cert is fetched and installed via setServerCertificate before any license requests are made. The URL is included in share links so FairPlay sessions are fully restorable.
  • Fix Decode error recovery — if Safari fires MEDIA_ERR_DECODE during the license round-trip (before the CKC arrives), the player resets src to clear the broken decode pipeline. Because setMediaKeys persists across src changes, the next encrypted event finds keys already installed and skips a full license round-trip.
Autoplay & Sharing
  • New Muted-autoplay fallback — playback now uses an attemptAutoPlay() helper that calls video.play() and, if blocked by browser autoplay policy (NotAllowedError), retries with video.muted = true. Muted autoplay is permitted in all browsers; the user can unmute afterwards. Applied to HLS (hls.js), native HLS (Safari), and DASH.
  • New Always-autoplay on shared URLs — share links now always include autoplay=true when a stream URL is present so the recipient lands on a playing stream without having to press Play. DASH autoplay is now driven from the STREAM_INITIALIZED hook (rather than the initialize call) so the muted-retry path works correctly.
DASH Quality Timeline
  • Fix DASH Quality switch labels for dash.js v4 and v5 — the QUALITY_CHANGE_RENDERED handler now supports both the v5 (event.oldRepresentation / event.newRepresentation objects) and v4 (event.oldQuality / event.newQuality integer indices) event shapes. Labels show height and kbps where available. ABR select is kept in sync with the currently playing quality when auto-switch is on.
v0.0.6 6 Aug 2026
Subtitles & Closed Captions
  • New HLS DASH Text Track Info Strip — replaces the external subtitle dropdown. When a stream carries text tracks the player controls area shows a compact strip of chips, one per track, labelled with language and exact format: TTML, WebVTT, CEA-608, CEA-708, SRT, or Image subtitles. The native in-player CC button handles track selection. Strip is hidden for streams with no text tracks and clears correctly when switching to a stream that lacks subtitles.
  • New DASH Format detection by codec — DASH MediaInfo codec strings are the primary signal: stpp / stpp.ttml.* → TTML, wvtt → WebVTT, c608 / tx3g → CEA-608, c708 → CEA-708. mimeType used as fallback.
  • New HLS Format detection for HLS tracks — instreamId (CC1–CC4 → CEA-608, SERVICE* → CEA-708), type: SUBTITLES field, URL extension (.vtt, .m3u8 sub-manifests, .srt, .ttml), and native track label as final fallback.
  • Fix DASH Subtitle pipeline not starting — dash.js v4 disables text streaming by default. Added streaming.text.defaultEnabled: true to the initial updateSettings call so text adaptation sets are loaded from the start.
  • Fix Stale text tracks on stream switch — when loading a stream without subtitles after one that had them, the strip now correctly clears. Fixed by only consulting the active player's own subtitle API; native TextTrack objects (which can linger after player teardown) are ignored while a managed player is alive.
DASH Quality Selection
  • Fix DASH Manual quality not sticking — two root causes fixed. (1) streaming.abr.ABRStrategy was rejected by dash.js v4's settings validator (renamed to abrStrategy). (2) setQualityFor was called with noImplicitSwitch = true, which kept ABR running and caused it to override the chosen quality immediately. Now uses updateSettings({ streaming: { abr: { autoSwitchBitrate: { video: false } } } }) followed by setQualityFor("video", index) (no third arg).
  • Fix DASH Bitrate list empty at init — added a MANIFEST_LOADED listener that triggers updateDashOptions as soon as the MPD is parsed, before STREAM_INITIALIZED. The auto/manual state now reads from getSettings().streaming.abr.autoSwitchBitrate when the legacy getAutoSwitchQualityFor API is absent.
Sharing & URL State
  • New Address bar sync on Play — when Play is clicked the browser address bar is updated via history.replaceState to the full shareable URL (stream URL + all config). Reloading the tab or pasting the URL restores the exact session.
  • New Two share icon buttons — a Share chip in the app header (top-right) and a compact Share button above the Stream URL field both copy the current player URL to the clipboard with a 2 s "Copied!" confirmation. All three share buttons (including the existing one in the actions row) share the same doShare() helper.
Charts
  • New Full-session graph view — buffer and bitrate charts no longer scroll; all data from the moment Play is pressed is retained and the entire session history is visible at once. As new samples arrive the x-axis compresses uniformly so the start point stays anchored at the left edge.
Bug Fixes & Polish
  • Fix Local file label opens file picker — removed the for attribute from the "Local file" label so clicking the label text no longer inadvertently triggers the file picker; only the native file input itself is interactive.
  • Fix DASH Quality and Audio controls inline — player controls area uses a two-column grid so Quality and Audio Track sit side-by-side in one row.
v0.0.5 27 Apr 2026
Diagnostics & Observability
  • New Stall Counter — two new stat cards track the number of rebuffer events and cumulative stall time across the session. Incremented on every waiting event; elapsed time added when playing resumes. Reset on each new playback session.
  • New HLS DASH Quality Switch Timeline — collapsible panel logs every ABR switch with a wall-clock timestamp, previous rendition, and new rendition (height + kbps). HLS hooks LEVEL_SWITCHED; DASH hooks QUALITY_CHANGE_RENDERED (video track only). Switch count shown in the panel header.
  • New Manifest Viewer — collapsible panel fetches the raw manifest text on Play and displays it in a scrollable pre block. A Copy button writes the full manifest to the clipboard. Skipped for local file sources.
  • New Response Header Inspector — shown inside the Manifest panel; captures x-cache, via, content-type, cdn-cache-control, cache-control, etag, last-modified, age, x-amz-cf-pop, x-served-by, and x-cache-hits from the manifest fetch. Falls back gracefully if CORS restricts header access.
  • New HLS DASH Segment Waterfall — canvas chart below the buffer/bitrate graphs showing a timeline of individual segment downloads. X-axis is wall-clock time relative to session start; each bar's width represents download duration. Detected via XHR interception on .ts, .m4s, .m4v, .m4a, .aac, and .webm requests. Displays last 25 segments; bar labels show duration in ms.
v0.0.4 27 Apr 2026
Utility
  • New Share URL — the Share button in the config panel encodes the full current setup (stream URL, type, DRM, playback toggles, custom headers, bitrate cap, ABR algorithm, simulated bandwidth) into URL query parameters. Paste the resulting link in any browser to instantly restore the exact configuration. A Copy button writes the URL to the clipboard via the Clipboard API with a execCommand fallback for older browsers. Only non-default values are included, keeping URLs short. On page load, restoreFromUrl() reads the query string and pre-fills all matching fields automatically.
v0.0.3 27 Apr 2026
Network & ABR Features
  • New HLS DASH Custom Request Headers — inject arbitrary key:value headers into every manifest and segment request. Useful for Authorization, CDN authentication tokens, or any custom header required by the origin. Enter one header per line in Key: Value format. HLS uses xhrSetup; DASH uses RequestModifier.
  • New HLS DASH Max Bitrate Cap — hard ceiling on the quality tier ABR can select. Prevents the player from ever requesting a rendition above the chosen bitrate, regardless of measured throughput. HLS maps the cap to the highest level index ≤ the target via autoLevelCapping; DASH uses streaming.abr.maxBitrate.video.
  • New DASH ABR Algorithm Selector — switch between dash.js ABR strategies without needing devtools. Available options: abrThroughput (default), abrBola (buffer-occupancy based), abrDynamic, abrL2A, and abrLoLP (optimised for low-latency streams). Applied via streaming.abr.ABRStrategy before initialisation.
  • New HLS DASH Simulated Bandwidth — override the player's perceived network throughput to test ABR decisions without throttling the OS or browser. Presets cover 2G / 3G / 4G and broadband speeds. HLS seeds abrEwmaDefaultEstimate and reinforces the value every 2 s; DASH sets initialBitrate and maxBitrate to the simulated value.
v0.0.2 27 Apr 2026
Bug Fixes
  • Fix HLS DASH Stream type detection with query parameters — URLs with anything after the file extension (e.g. ?bc_token=…, SSAI redirect URLs) were not detected as HLS or DASH, causing playback to fail. Detection now extracts the URL pathname via new URL() before checking the extension, stripping query strings and fragments automatically.
